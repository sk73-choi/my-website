# 바이브 코더용 Web UI 주요 컴포넌트

AI에게 "예쁘게 만들어 줘"라고 하면 결과는 매번 복불복입니다. 반대로 **정확한 UI 이름**과 **원하는 동작**, **조건**을 말하면 AI는 한 번에 의도대로 만들어 냅니다.

이 글은 바이브 코딩에서 가장 자주 쓰는 **24가지 웹 UI 패턴**을 3개 영역으로 나눠 정리했습니다. 각 항목에는 다음 세 가지가 들어 있습니다.

- **한 줄 정의** — 이게 뭔지, 언제 쓰는지
- **LIVE DEMO** — 직접 클릭·스크롤·호버해 볼 수 있는 실제 동작 예제
- **프롬프트 템플릿** — 코드 블록 우측 상단 **복사** 버튼으로 바로 가져다 쓰기

## 프롬프트 3단계 공식

모든 템플릿은 아래 공식을 따릅니다.

| 단계 | 무엇을 말하나 | 예시 |
|---|---|---|
| ① **UI 표준 용어** | 만들 대상의 정확한 이름 | `[모달 다이얼로그]`, `[드로어]` |
| ② **원하는 동작** | 어떻게 보이고 움직이는지 | 화면 중앙에 띄우고, 뒤를 어둡게 |
| ③ **트리거·제약 조건** | 언제 열리고 닫히는지, 예외 상황 | ESC·바깥 클릭 시 닫기, 768px 이하에선 85% 폭 |

> ❌ "삭제할 때 확인창 하나 띄워 줘"
> ✅ "삭제 버튼 클릭 시 [**모달 다이얼로그**]를 화면 중앙에 띄우고, 뒤에는 50% 반투명 [**오버레이**]를 깔아 스크롤을 막아 줘. 취소·바깥 클릭·**ESC** 로 닫히게 해 줘."

같은 요청이지만 아래쪽은 AI가 추측할 부분이 거의 없습니다. 이 차이가 결과물의 완성도를 결정합니다.

## ① 레이아웃 영역 (Layout Patterns)

페이지의 **뼈대**입니다. 요소를 어디에, 어떤 비율로, 화면 크기에 따라 어떻게 재배치할지를 정합니다.

### 히어로 섹션 & CTA (Hero Section)

**Hero Section** 은 사이트에 들어오자마자 보이는 첫 화면으로, 서비스가 무엇인지 3초 안에 알려 주는 영역입니다. **CTA(Call to Action)** 는 "무료로 시작하기"처럼 방문자가 *다음 행동*을 하도록 유도하는 눈에 띄는 버튼입니다.

<div data-demo="hero"></div>

```text
웹사이트 첫 진입 영역에 제품의 정체성을 한눈에 전달하는 [히어로 섹션]을 구성해 줘.
좌측(모바일은 상단)에는 서비스 가치를 압축한 헤드라인과 서브텍스트를, 우측(모바일은 하단)에는 대시보드 미리보기 이미지를 배치해 줘.
그 아래 중앙에는 배경과 대비되는 강조 색상의 [CTA 버튼]을 두고, 클릭 시 페이지 하단 회원가입 폼으로 부드럽게 스크롤 이동하게 해 줘.
섹션 전체에 가로 패딩과 수직 여백을 넉넉히 확보해 줘.
```

> 💡 CTA는 **페이지 전체에서 가장 튀는 색**이어야 합니다. 주변 버튼과 같은 색이면 CTA가 아닙니다.

### 반응형 레이아웃 (Responsive Layout)

화면 폭에 따라 **열 개수·배치가 자동으로 바뀌는** 레이아웃입니다. 기준이 되는 폭을 **브레이크포인트(breakpoint)** 라고 부릅니다.

<div data-demo="responsive"></div>

```text
콘텐츠 목록 영역을 CSS Grid 기반의 [반응형 레이아웃]으로 구현해 줘.
뷰포트 너비에 따라 데스크톱(1024px 이상) 3열, 태블릿(768px~1023px) 2열, 모바일(767px 이하) 1열로 자동 재배치되도록 breakpoint를 설정해 줘.
열 사이 간격(gap)은 24px로 통일하고, 카드는 고정 폭이 아니라 열 너비에 맞춰 유연하게 늘어나게 해 줘.
```

> 💡 데모는 이 박스 폭 기준(컨테이너 쿼리)으로 시연합니다. 실제 사이트에선 Tailwind 의 `sm:` `md:` `lg:` 접두사가 바로 이 브레이크포인트입니다.

### 카드 레이아웃 (Card Layout)

같은 형식의 정보를 **독립된 상자(카드)** 에 담아 반복 배치하는 방식입니다. 아이콘 → 제목 → 설명처럼 **카드 내부 계층**을 정해 주는 것이 핵심입니다.

<div data-demo="card"></div>

```text
기능 소개 섹션에 반복되는 정보를 구조화해 보여주는 [카드 레이아웃]을 적용해 줘.
각 카드는 독립된 흰색 컨테이너로 만들고, 내부는 상단 아이콘 → 중간 볼드 타이틀 → 하단 2~3줄 요약 설명 순서의 계층 구조로 잡아 줘.
카드 테두리는 은은한 1px 보더와 8px 라운드 코너(border-radius)를 적용하고, 다크 모드에선 어두운 배경으로 바꿔 줘.
```

### 벤토 그리드 (Bento Grid)

일본 도시락(벤토) 칸막이처럼 **크기가 다른 칸을 비대칭으로** 배치한 격자입니다. 가장 중요한 기능을 큰 칸에 두어 시선을 끌 수 있어 애플·SaaS 랜딩 페이지에서 많이 씁니다.

<div data-demo="bento"></div>

```text
서비스 주요 기능을 비대칭 격자로 시각화하는 [벤토 그리드] 레이아웃을 만들어 줘.
핵심 기능인 '데이터 분석'은 가로 2칸 x 세로 2칸의 대형 카드로 강조하고, 나머지 부가 기능 4개는 1칸짜리 소형 카드로 배치해 줘.
데스크톱에서는 4열 x 2행 그리드를 유지하고, 화면 너비가 768px 미만이면 모든 카드가 같은 크기의 1열 구조로 세로 정렬되게 해 줘.
```

### 사이드바 레이아웃 (Sidebar Layout)

왼쪽에 **고정 메뉴**, 오른쪽에 **작업 영역**을 둔 구조입니다. 관리자 화면·대시보드의 표준이며, 모바일에선 **햄버거 메뉴(☰)** 로 숨기는 것이 일반적입니다.

<div data-demo="sidebar"></div>

```text
대시보드 페이지에 좌측 네비게이션과 우측 작업 공간이 분리된 [사이드바 레이아웃]을 구축해 줘.
좌측 사이드바는 폭 260px로 고정(sticky)하고, 메뉴 클릭 시 페이지 전체 리로드 없이 우측 메인 콘텐츠만 바뀌도록 클라이언트 라우팅을 구성해 줘. 현재 메뉴는 강조 색으로 표시해 줘.
모바일(1024px 미만)에서는 사이드바를 숨기고, 좌상단 햄버거 버튼을 누르면 왼쪽에서 오버레이로 슬라이드되어 열리게 해 줘. 메뉴를 고르거나 바깥을 누르면 닫혀야 해.
```

### 스티키 헤더 (Sticky Header)

스크롤해도 **화면 맨 위에 붙어 따라오는** 상단 메뉴 바입니다. 스크롤이 시작되면 그림자·블러를 넣어 본문과 겹쳐 보이지 않게 하는 것이 포인트입니다.

<div data-demo="sticky-header"></div>

```text
페이지 상단 글로벌 내비게이션 바를 [스티키 헤더]로 구현해 줘.
아래로 스크롤해도 뷰포트 최상단(position: sticky; top: 0)에 붙어 있고, z-index는 본문보다 위로 유지해 줘.
처음엔 투명 배경이다가, 스크롤이 시작되는 즉시(scrollY > 0) 반투명 배경 + 배경 블러(backdrop-filter) + 하단 드롭 섀도우가 부드럽게 나타나 본문과 구분되게 해 줘.
```

### 스플릿 레이아웃 (Split Layout)

화면을 **좌우로 나눠** 한쪽엔 이미지, 다른 쪽엔 설명을 두는 구조입니다. 모바일에선 자동으로 **위아래 세로 스택**으로 바뀌어야 합니다.

<div data-demo="split"></div>

```text
제품 상세 설명 영역에 좌우를 균등 분할하는 [스플릿 레이아웃]을 적용해 줘.
데스크톱에서는 좌측 50%에 제품 데모 스크린샷을, 우측 50%에 제목·설명 텍스트·체크리스트를 세로 중앙 정렬로 나란히 배치해 줘.
화면 너비가 768px 이하가 되면 좌우 배치를 해제하고 이미지가 위, 텍스트가 아래인 세로 스택(Vertical Stack) 구조로 자동 전환되게 해 줘.
```

## ② 컴포넌트 영역 (UI Components)

화면 안에서 **사용자가 직접 조작하는 부품**들입니다. "언제 열리고, 언제 닫히는가"를 프롬프트에 명확히 적는 것이 가장 중요합니다.

### 탭 (Tabs)

같은 자리에서 **주제별 내용을 바꿔 보여주는** 컴포넌트입니다. 페이지를 이동하지 않고 패널만 교체합니다.

<div data-demo="tabs"></div>

```text
콘텐츠 영역 안에서 화면 전환 없이 주제별 내용을 교체해 보여주는 [탭] 컴포넌트를 만들어 줘.
상단에 '개요', '기술 스펙', '가격 정책' 탭 버튼을 배치하고, 탭을 클릭하거나 키보드 좌우 방향키로 이동하면 해당 패널만 즉시 렌더링되게 해 줘.
활성 탭 하단에는 진한 인디케이터 라인이 부드럽게 슬라이드되며 따라가게 하고, 접근성을 위해 role="tablist/tab/tabpanel"과 aria-selected를 적용해 줘.
```

### 아코디언 (Accordion)

제목을 누르면 내용이 **아래로 펼쳐지고 다시 누르면 접히는** 컴포넌트입니다. FAQ에 가장 많이 씁니다.

<div data-demo="accordion"></div>

```text
자주 묻는 질문(FAQ) 섹션을 수직 확장형 [아코디언] 컴포넌트로 구현해 줘.
각 질문 행 우측에 화살표 아이콘을 넣어 열리면 180도 회전하게 하고, 질문 클릭 시 답변 영역이 높이 애니메이션으로 자연스럽게 펼쳐지고 다시 누르면 닫히게 해 줘.
한 번에 하나의 질문만 열리도록 하고, 접근성을 위해 질문 버튼에 aria-expanded / aria-controls 속성을 연동해 줘.
```

### 모달 & 오버레이 (Modal / Dialog & Overlay)

**모달**은 화면 중앙에 떠서 사용자의 응답을 받을 때까지 다른 조작을 막는 창이고, **오버레이(백드롭)** 는 그 뒤를 덮는 반투명 막입니다. 삭제처럼 되돌릴 수 없는 작업의 확인에 씁니다.

<div data-demo="modal"></div>

```text
'데이터 영구 삭제' 버튼 클릭 시 확인을 요청하는 [모달 다이얼로그]를 화면 중앙에 띄워 줘.
모달 뒤 전체 화면에는 클릭과 뒤쪽 페이지 스크롤을 차단하는 50% 반투명 검은색 [오버레이(백드롭)]를 깔아 줘.
'삭제 확인' 버튼 외에 취소 버튼 클릭, 오버레이(모달 바깥) 클릭, 키보드 ESC 입력 시 모달이 즉시 닫히게 해 줘.
모달이 열리면 포커스를 '취소' 버튼으로 옮기고 role="dialog", aria-modal="true"를 지정해 줘.
```

> 💡 **닫는 방법 3가지(취소·바깥 클릭·ESC)** 를 적지 않으면 AI가 X 버튼 하나만 만드는 경우가 많습니다.

### 드로어 (Drawer)

화면 **가장자리에서 미끄러져 나오는 패널**입니다. 모달과 달리 메인 화면을 다 가리지 않아 필터·설정처럼 "보면서 조정"하는 작업에 적합합니다.

<div data-demo="drawer"></div>

```text
우측 상단의 필터 아이콘을 클릭하면 화면 오른쪽에서 부드럽게 슬라이드되어 나오는 [드로어] 패널을 만들어 줘.
메인 페이지의 맥락을 가리지 않도록 전체 너비의 30%(최소 300px, 모바일은 85%)만 차지하게 하고, 뒤에는 옅은 오버레이를 깔아 줘.
드로어 외부 영역을 클릭하거나 ESC 키를 누르면 오른쪽 바깥으로 슬라이드 아웃되며 닫히게 하고, 하단 '적용하기' 버튼을 누르면 선택한 필터를 반영한 뒤 닫히게 해 줘.
```

### 드롭다운 (Dropdown)

버튼을 누르면 **아래로 선택지 목록이 펼쳐지는** 메뉴입니다. 정렬·필터·계정 메뉴 등에 씁니다. **바깥 클릭 시 닫기(click-outside)** 를 빼먹기 쉽습니다.

<div data-demo="dropdown"></div>

```text
목록 상단의 정렬 버튼을 트리거로 하는 [드롭다운] 메뉴 컴포넌트를 작성해 줘.
버튼 클릭 시 아래로 '최신순', '인기순', '이름순' 옵션 리스트가 열리고, 옵션을 선택하면 버튼 텍스트가 해당 항목으로 바뀌고 목록이 그 기준으로 정렬되며 메뉴가 닫히게 해 줘.
현재 선택된 옵션 옆에는 체크 아이콘을 표시하고, 드롭다운 바깥 아무 곳이나 클릭하거나 ESC를 누르면 자동으로 닫히는(click-outside) 로직을 포함해 줘.
```

### 툴팁 (Tooltip)

아이콘에 마우스를 올리면 뜨는 **작은 말풍선 설명**입니다. 공간이 부족하면 위치를 반대로 뒤집는 **플리핑(flipping)** 처리가 완성도를 가릅니다.

<div data-demo="tooltip"></div>

```text
통계 카드 옆 물음표 도움말 아이콘에 마우스를 올리거나 키보드 포커스가 닿으면 부가 설명을 보여주는 [툴팁]을 구현해 줘.
아이콘 정중앙 위쪽에 작고 어두운 말풍선(꼬리 포함) 형태로 띄우고, 마우스가 벗어나거나 포커스를 잃으면 150ms 후 페이드아웃되게 해 줘.
위쪽 공간이 부족해 화면 상단 경계와 맞닿을 경우 자동으로 아이콘 아래쪽으로 위치를 반전하는 플리핑(flipping) 처리를 적용하고, role="tooltip"과 aria-describedby를 연결해 줘.
```

### 토스트 / 스낵바 (Toast / Snackbar)

작업 결과를 **잠깐 띄웠다가 저절로 사라지는** 가벼운 알림입니다. 사용자의 흐름을 막지 않는다는 점에서 모달과 다릅니다.

<div data-demo="toast"></div>

```text
설정 저장 성공 시 작업 완료를 알리는 가벼운 [토스트] 알림을 구현해 줘.
화면 우측 하단(모바일은 중앙 하단)에 체크 아이콘과 함께 '변경 사항이 성공적으로 저장되었습니다' 메시지를 띄우고, 3초 후 페이드아웃되며 DOM에서 자동 제거되게 해 줘.
우측에는 즉시 닫을 수 있는 'X' 버튼을, 하단에는 남은 시간을 보여주는 얇은 진행 막대를 넣어 주고, 여러 번 저장하면 토스트가 위로 쌓이게 해 줘.
```

### 캐러셀 (Carousel)

여러 장의 카드를 **가로로 넘겨 보는** 슬라이더입니다. 화살표·점 인디케이터·스와이프·자동 넘김을 모두 조건으로 적어 주는 것이 좋습니다.

<div data-demo="carousel"></div>

```text
고객 리뷰 섹션에 피드백 카드를 가로로 순환 탐색하는 [캐러셀] 슬라이더를 만들어 줘.
좌우 화살표 버튼과 하단 인디케이터 점(dots)을 배치하고, 데스크톱에서는 3장, 모바일에서는 1장씩 보이게 해 줘. 마지막에서 다음을 누르면 처음으로 돌아가야 해.
모바일 터치를 위해 좌우 스와이프 제스처를 지원하고, 3초마다 자동으로 넘어가되 마우스를 올리거나 포커스가 있으면 자동 넘김(auto-play)이 일시 정지되게 해 줘.
```

### 스켈레톤 로딩 (Skeleton Loading)

데이터를 불러오는 동안 **실제 화면과 똑같은 모양의 회색 틀**을 먼저 보여주는 기법입니다. 로딩이 끝나도 레이아웃이 밀리지 않아(CLS 방지) 훨씬 빠르게 느껴집니다.

<div data-demo="skeleton"></div>

```text
API에서 데이터 목록을 비동기로 가져오는 동안 빈 화면이나 스피너 대신 [스켈레톤 로딩] 화면을 표시해 줘.
실제 카드와 완전히 같은 크기로 원형 프로필 플레이스홀더와 텍스트 줄 높이의 직사각형 블록을 배치하고,
밝은 회색에서 중간 회색으로 반복 이동하는 은은한 shimmer 애니메이션을 적용해 줘. 데이터가 도착해 교체될 때 누적 레이아웃 이동(CLS)이 없어야 해.
```

## ③ 인터랙션·시각 효과 (Interactions & Effects)

같은 화면이라도 **움직임과 질감**이 더해지면 완성도가 확 올라갑니다. 단, 과하면 산만하므로 **속도(ms)·거리(px)·조건**을 숫자로 지정하세요.

### 호버 이펙트 (Hover Effect)

마우스를 올렸을 때 요소가 **반응하는 시각 변화**입니다. "이건 누를 수 있다"는 신호를 줍니다.

<div data-demo="hover"></div>

```text
대시보드 데이터 카드 컴포넌트에 마우스를 올렸을 때 작동하는 [호버 이펙트]를 적용해 줘.
마우스를 올리면 카드가 translateY(-4px)만큼 살짝 떠오르고, 하단 드롭 섀도우가 진해지며, 보더 색상이 서비스 메인 포인트 컬러로 바뀌게 해 줘.
마우스가 벗어나면 300ms CSS transition으로 부드럽게 원래 상태로 복귀하고, 키보드 포커스(focus-visible) 시에도 같은 효과가 나게 해 줘.
```

### 스크롤 리빌 (Scroll Reveal)

스크롤해서 요소가 **화면에 들어오는 순간 나타나는** 효과입니다. `Intersection Observer` 로 진입 시점을 감지합니다.

<div data-demo="scroll-reveal"></div>

```text
랜딩 페이지를 스크롤할 때 각 기능 소개 섹션이 뷰포트에 20% 이상 진입하는 시점을 감지해 나타나는 [스크롤 리빌] 효과를 적용해 줘.
요소가 화면 밖에 있을 때는 opacity 0, translateY(30px) 상태로 두었다가, Intersection Observer API로 진입을 감지하면 opacity 1과 원래 위치로 0.7초 동안 슬라이드 업되며 나타나게 해 줘.
한 번 나타난 요소는 다시 숨기지 말고, prefers-reduced-motion 환경에선 애니메이션 없이 바로 보이게 해 줘.
```

### 스태거 애니메이션 (Stagger Animation)

여러 요소가 **동시에가 아니라 순서대로 시간차**를 두고 등장하는 효과입니다. 목록에 리듬감이 생깁니다.

<div data-demo="stagger"></div>

```text
검색 결과 카드 6개가 화면에 마운트될 때 한꺼번에 번쩍이며 나타나지 않도록 [스태거 애니메이션]을 적용해 줘.
첫 번째 카드가 나타난 뒤 다음 카드가 100ms 간격의 딜레이(animation-delay 또는 Framer Motion staggerChildren)를 두고 순차적으로 페이드인되며,
동시에 scale 0.95 → 1.0 으로 미세하게 커지면서 리듬감 있게 렌더링되게 구현해 줘.
```

### 스무스 트랜지션 (Smooth Transition)

색·테두리 같은 상태 변화가 **뚝 바뀌지 않고 서서히** 변하게 하는 처리입니다. 눈에 잘 안 띄지만 "고급스럽다"는 인상의 대부분을 만듭니다.

<div data-demo="smooth-transition"></div>

```text
모든 버튼, 링크, 탭의 호버 및 활성 상태 변경 시 깜빡이거나 뚝뚝 끊기지 않도록 [스무스 트랜지션]을 전역 적용해 줘.
transition을 200ms cubic-bezier(0.4, 0, 0.2, 1)로 설정해 배경색, 글자색, 보더 색, 그림자 변화가 0.2초에 걸쳐 매끄럽게 이어지게 해 줘.
단, transition: all 대신 변하는 속성(color, background-color, border-color, box-shadow)만 지정해 성능 저하를 막아 줘.
```

### 글래스모피즘 (Glassmorphism)

**반투명 유리** 같은 질감입니다. 반투명 배경 + 배경 블러(`backdrop-filter`) + 얇은 흰 테두리가 3요소입니다. 이 사이트의 카드들도 이 스타일입니다.

<div data-demo="glass"></div>

```text
고정 헤더와 내비게이션 카드에 뒤 배경이 반투명하게 비치는 [글래스모피즘] 스타일을 적용해 줘.
반투명 배경색 rgba(255, 255, 255, 0.65)와 backdrop-filter: blur(12px), 미세한 1px 반투명 흰색 보더를 부여해 줘.
단, 본문 텍스트 가독성을 해치지 않도록 글자와 배경의 명도 대비(Contrast Ratio)를 WCAG AA 기준(최소 4.5:1) 이상으로 유지해 줘.
```

> 💡 투명도를 너무 낮추면 예쁘지만 글자가 안 읽힙니다. 데모에서 슬라이더를 끝까지 내려 보세요.

### 패럴렉스 스크롤링 (Parallax Scrolling)

배경과 전경이 **서로 다른 속도로 스크롤**되어 깊이감을 주는 효과입니다. 멀미를 유발할 수 있어 **움직임 줄이기 설정 대응**이 필수입니다.

<div data-demo="parallax"></div>

```text
메인 히어로 섹션의 배경 그래픽 오브젝트에 스크롤 속도 차이를 이용한 [패럴렉스 스크롤링] 효과를 부여해 줘.
본문 텍스트가 1의 속도로 스크롤될 때 배경 원형 그래픽은 0.3의 속도로 느리게 이동해 깊이감을 만들어 줘.
멀미를 유발하지 않도록 이동 폭을 최소화하고, OS 설정의 움직임 줄이기(prefers-reduced-motion: reduce)가 켜진 환경에서는 효과를 완전히 비활성화해 줘.
```

### 스크롤 스냅 (Scroll Snap)

스크롤을 멈추면 화면이 **섹션 시작점에 딱 맞춰 정렬**되는 기능입니다. 풀스크린 스토리텔링 페이지나 가로 이미지 갤러리에 씁니다. CSS 두 줄로 됩니다.

<div data-demo="scroll-snap"></div>

```text
전체 화면(100vh) 슬라이드 형태의 제품 스토리텔링 페이지를 만들고 CSS [스크롤 스냅]을 적용해 줘.
스크롤 컨테이너에 scroll-snap-type: y mandatory를, 각 풀스크린 섹션에 scroll-snap-align: start를 지정해 줘.
마우스 휠이나 트랙패드 스크롤을 멈췄을 때 화면이 중간에 걸치지 않고 가장 가까운 섹션 시작점에 맞춰 정렬되게 하고, 우측에 현재 섹션을 표시하는 점 인디케이터를 넣어 줘.
```

### 마이크로 인터랙션 (Micro-interaction)

버튼을 눌렀을 때 **즉각적이고 작은 피드백**(스피너, 체크, 살짝 튀는 움직임)입니다. "내 클릭이 먹혔다"는 확신을 줍니다.

<div data-demo="micro"></div>

```text
'저장' 및 '즐겨찾기' 버튼에 클릭 즉시 시각 피드백을 주는 [마이크로 인터랙션]을 구현해 줘.
버튼 클릭 시 아이콘 자리에 스피너가 돌며 로딩 상태를 보여주고, 완료되면 0.2초 동안 버튼이 1.1배 커졌다 돌아오는 바운스 효과와 함께
저장 버튼은 초록색 배경의 체크 아이콘('저장됨')으로, 즐겨찾기 버튼은 하트 아이콘이 채워지는 상태로 바뀌게 해 줘. 로딩 중 중복 클릭은 무시해 줘.
```

### 데이터 분석 대시보드 단일 프롬프트

사용 요소: 사이드바 레이아웃 · 반응형 레이아웃 · 스켈레톤 로딩 · 카드 레이아웃 · 툴팁 · 마이크로 인터랙션 · 토스트 · 오버레이 · 모달

```text
Next.js와 TypeScript 기반의 데이터 분석 대시보드 메인 뷰를 개발해 줘.

4. 피드백: 필터 조건을 바꾸고 저장 버튼을 누르면 버튼에 체크 아이콘이 튀어나오는 [마이크로 인터랙션]을 주고, 화면 하단에 3초간 머무는 [토스트] 알림을 띄워 줘.
5. 위험 작업: 데이터 초기화 버튼 클릭 시 배경을 어둡게 막는 [오버레이]와 중앙 [확인 모달]을 띄워 최종 승인을 받아 줘. ESC·취소·바깥 클릭으로 닫혀야 해.
```
