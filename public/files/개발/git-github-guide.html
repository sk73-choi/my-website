Git 초기 설정

사용자 정보 및 전역 설정
사용자 이름 & 이메일 등록

커밋에 기록될 이름과 이메일을 설정합니다. GitHub 계정과 동일한 이메일을 사용하면 커밋 히스토리가 GitHub 프로필에 연결됩니다.

PowerShell
git config --global user.name "홍길동"
git config --global user.email "your@email.com"
기본 브랜치명 설정
PowerShell
git config --global init.defaultBranch main
Windows 줄바꿈 처리

Windows는 CRLF, Linux/Mac은 LF를 사용합니다. 아래 설정으로 충돌을 방지합니다.

PowerShell
git config --global core.autocrlf true
설정 확인
PowerShell
git config --list --global

GitHub 계정 & 인증 설정

SSH 키 또는 Personal Access Token(PAT) 설정
ℹ️

GitHub은 비밀번호 직접 입력을 지원하지 않습니다. SSH 키 방식(권장)이나 PAT(Personal Access Token) 방식 중 하나를 사용해야 합니다.

방법 A: SSH 키 생성 (권장)
PowerShell
# SSH 키 생성 (Ed25519 알고리즘)
ssh-keygen -t ed25519 -C "your@email.com"
# 저장 위치: Enter (기본값 사용)
# passphrase: 빈칸 Enter (간편) 또는 비밀번호 설정

# 공개키 내용 확인 (복사용)
cat ~/.ssh/id_ed25519.pub

출력된 공개키 전체(ssh-ed25519 ... 까지)를 복사한 후:

GitHub → Settings → SSH and GPG keys → New SSH key → 붙여넣기

PowerShell — 연결 테스트
ssh -T git@github.com
# 성공: Hi username! You've successfully authenticated...
방법 B: PAT (Personal Access Token)

GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token

권한(Scope): repo 체크 → 생성 후 토큰 복사 (다시 볼 수 없음)

⚠️

PAT를 사용할 경우 git push 시 비밀번호 입력란에 PAT를 입력합니다. Windows 자격 증명 관리자에 저장되어 이후엔 자동 입력됩니다.

일상 작업 흐름

Claude Code 세션과 Git 커밋의 통합 루틴
작업 시작 │ ├── git pull origin main ← 최신 상태 동기화 │ ├── claude code 세션 시작 │ └── 기능 개발 / 분석 코드 작성 │ ├── git status ← 변경 파일 확인 ├── git diff ← 내용 검토 ├── git add [파일명] ← 선택적 스테이징 ├── git commit -m "feat: ..." ← 의미 단위 커밋 │ └── git push origin [브랜치] ← GitHub 백업
Claude Code 세션과 Git 연계 예시
PowerShell — 하루 작업 예시
# 1. 작업 시작 전 최신 상태로
git pull

# 2. 기능 브랜치 생성 (큰 작업일 때)
git checkout -b feature/add-failure-rate-analysis

# 3. Claude Code 작업 후 — 변경 내용 확인
git status
git diff analysis/rdm_analysis.py

# 4. 특정 파일만 스테이징
git add analysis/rdm_analysis.py
git add dashboard/app.py

# 5. 커밋
git commit -m "feat: 불량률 추이 분석 함수 추가"

# 6. Push
git push origin feature/add-failure-rate-analysis

브랜치 전략

개인 프로젝트에 맞는 단순화된 Git Flow
main ●─────────────────────────────────● (안정 버전) ╲ ╱ develop ●──────●──────●──────● (통합 개발) ╲ ╱ feature/xxx ●──────● (기능 작업)
브랜치 기본 명령어
PowerShell
# 브랜치 목록 확인
git branch -a

# 새 브랜치 생성 & 이동
git checkout -b feature/dashboard-redesign

# 브랜치 이동
git checkout develop

# feature → develop 병합
git checkout develop
git merge --no-ff feature/dashboard-redesign
git push origin develop

# 완료된 feature 브랜치 삭제
git branch -d feature/dashboard-redesign
개인 프로젝트 단순 전략 (추천)
💡

혼자 작업한다면 main 하나만 써도 충분합니다. 단, 실험적인 변경은 feature/xxx 브랜치를 만들어 분리하세요. 망해도 main은 안전합니다.

자주 발생하는 문제 해결

Windows + GitHub 환경에서 흔히 겪는 오류
오류: "Please tell me who you are"

사용자 정보가 설정되지 않은 경우입니다.

해결
git config --global user.name "이름"
git config --global user.email "이메일"
오류: push rejected / remote contains work

원격 저장소에 로컬에 없는 커밋이 있는 경우입니다.

해결
# 먼저 pull 후 push
git pull --rebase origin main
git push origin main
오류: CRLF / LF 경고
해결
git config --global core.autocrlf true
실수로 민감한 파일을 커밋한 경우
해결 — 마지막 커밋에서 파일 제거
# 파일을 Git 추적에서만 제거 (로컬 파일 유지)
git rm --cached config/secrets.py
# .gitignore에 추가 후
git commit -m "chore: 민감 파일 추적 제거"
⚠️

이미 원격에 push 했다면 Git 히스토리에 남습니다. 완전 제거는 git filter-branch 또는 BFG Repo Cleaner를 사용해야 합니다.

merge conflict 발생 시
해결 절차
# 충돌 파일 확인
git status

# 충돌 파일 직접 편집 후 (<<<, ===, >>> 마커 제거)
git add [충돌파일]
git commit

권장 운영 루틴

지속 가능한 버전 관리 습관
일일 루틴
  • ✓
    작업 시작 전 git pull로 최신화
  • ✓
    Claude Code 세션 끝낼 때 변경사항 커밋
  • ✓
    하루 마무리에 git push로 백업
  • 커밋 메시지는 "무엇을" + "왜"를 포함하도록
주간 루틴
  • git log --oneline -20으로 작업 흐름 검토
  • 완료된 feature 브랜치 정리 (삭제)
  • CLAUDE.md 내용 업데이트 & 커밋
  • develop → main 안정 버전 병합
Claude Code와 Git의 황금 조합
🚀

Claude Code 세션 시작 시: "지난 커밋 이후 변경사항을 git diff로 보여줘. 오늘 작업할 내용은 [X]야" 라고 컨텍스트를 제공하면 Claude가 더 정확하게 이어서 작업할 수 있습니다.

💡

Claude Code에게 Git 작업 위임 가능: "변경된 파일들을 적절한 단위로 나눠서 커밋 메시지와 함께 staging해줘" 처럼 요청할 수 있습니다. Claude Code는 터미널 명령어를 직접 실행할 수 있습니다.
